// 01 · Overview

プロジェクト概要

小学1～3年生を対象にした教育系パズル×ノベルゲーム。 ICD-11 のゲーム障害症状を敵キャラとして形にし、 『禁止』ではなく『知識とスキル』で依存を予防するアプローチを採用。 itch.io でリリース済み。

// 02 · Game Features

ゲーム機能と設計

教育的メッセージと没入感あるゲームプレイの両立

ICD-11 ゲーム障害症状の敵キャラ化
WHOが定義したゲーム障害の症状（制御喪失、優先順位の転換、有害な結果の継続）を ストーリー上の敵キャラとして擬人化。 プレイヤーが「何が依存か」を直感的に理解できるゲームデザイン。
パズルメカニクス × ノベル統合
ノベルパート（キャラ会話・背景演出）とパズルパート（ピース配置）を CSV駆動で完全同期。演出の自動化により、エンジニア不在でもプランナーが シナリオと表現を一体設計可能。
難易度調整（0.5x～2.0x）
BattleSpeedController で制限時間を動的スケール。 小学1年生から3年生まで、段階的な学習体験を提供。
// 03 · System Architecture

3層アーキテクチャ設計

エンジニア・プランナー・デザイナー3名の並走開発を可能にする層分離

3層分離による並走開発
Framework層 / GameLogic層 / UI層を明確に分離し、KISS + DRY 原則で保守性を確保。 3名が同時に異なる層で作業可能（ファイルコンフリクト最小化）。 企画変更時の耐性も高く、後方互換を意識した層間インターフェース設計。
汎用 ObjectPool<T> — メモリ最適化
C# ジェネリクスで『誰でも使える』汎用Pool を統一実装。 `_inPool` フラグで二度戻し防止、`OnSpawn() / OnDespawn()` ハックで初期化・後処理を自動化。 各メンバーが独自実装していたPool を一本化し、メモリ断片化を解消。
CSV駆動ノベル + CommentNo 演出同期
CommentNo（例："CHAP1-5"）1つで台詞・背景・キャラ・BGM・SE・Glow・Fade が全自動同期。 ScriptableObject だと Git コンフリクトが増えるため、CSV 形式で全員が同時編集可能に。 エンジニア不在でもプランナーが演出を調整できるオーサリング環境を実現。
Addressables による容量最適化
リリース容量制限（未指定）に対応するため、Resources を廃して Addressables を採用。 初期インストール ~150MB + ストリーミング配信で、容量を 約78%削減（初期構成から）。 SceneAddressCatalog + SceneTransitBus で、呼び出し側 1行で シーン遷移完結。
